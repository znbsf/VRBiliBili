# PiliPlus 空间版 V1：功能与 UI 设计稿

日期：2026-09-24。本页保留当时的设计基线。2026-10-03 用户实机反馈后明确取消空间视频路线，当前先完善基础 PiliPlus 的 Quest 大屏移植；当前实现及人工待验收项见 [Quest 客户端说明](QUEST-CLIENT.md)。

## 1. 产品定义与设计顺序

把 PiliPlus 的找片和播放体验变成 Quest 3 上可舒服使用的空间大屏。第一版围绕一个人、一段播放、一组可恢复的窗口。默认安静，需要时展开选集、评论和弹幕。

工作顺序：功能边界 → 用户流程 → 可点击原型 → Quest 上的等比例摆放与输入验证 → 修订设计 → 确定技术模块 → 开发。无需等每个像素定稿才研究可行性；桌面原型确认流程，头显原型确认距离、字号、遮挡、手势和舒适度。现有调研只作为参考，当前不开展客户端开发。

## 2. 首版范围

| 范围 | 功能 | 首版判断 |
| --- | --- | --- |
| 找内容 | 推荐、分区筛选、搜索、视频详情、分 P/合集入口 | 必需；登录前可以探索公开内容 |
| 个人内容 | 登录入口、稍后再看、历史记录、断点续播 | 必需；数据权限和接口以 PiliPlus 实际能力为准 |
| 看视频 | 播放/暂停、进度、上一/下一段、画质、倍速、音量、字幕、结束状态、失败重试 | 必需；画质只列实际可用项，字幕只在有轨道时可选 |
| 空间 | 主屏移动/缩放、选集和评论组件、锁定、成组移动、一键召回、布局保存 | 必需；默认只有主屏，最多两个辅助面板 |
| 环境 | 明暗调节，影院/透视环境入口 | 必需；原型以房间插画表达透视意图，真实透视须真机验证 |
| 普通弹幕 | 开关、密度、字号、字幕避让 | 必需；不开启立体效果也能完整使用 |
| 河流弹幕 | 主屏下方独立通道，低密度，不穿字幕和控制区 | 有条件试用；须通过舒适度和性能评估再纳入发布 |
| 跳出、朗读 | 用户点选后一次性预览，随时停止 | 实验预览；不列为 V1 发布承诺 |
| 后续 | 笔记窗口、动态与完整账号管理、多视频、多人观影、180°/360°、自由嵌入其他 App | 不进入首版 |

“组件化”指这个应用里的选集、评论等组件能分开摆放，不代表能把任意第三方 Android App 塞进播放器。透视、视频和面板透明度是三个不同设置；视频默认且首版始终不透明。

## 3. 信息架构

```text
发现 ── 搜索/分区 ── 视频详情 ── 空间播放
  │                                    │
  └── 继续观看                         ├── 选集组件
我的 ── 稍后再看 / 历史 ────────────────┤── 评论组件
  └── 登录入口                         ├── 弹幕设置
                                       ├── 布局与摆放
                                       └── 观看设置
```

发现和我的共用一个内容面板，详情在这个面板内替换内容。开始播放后收起内容面板；用户主动返回时暂停并保留进度。播放器底部的短工具栏按需唤出，设置在一次只开一个的设置区域内展示，不额外占据常驻空间窗口。

## 4. 关键流程与页面

### A. 第一次使用

进入发现 → 浏览公开内容或搜索 → 打开详情 → 播放。登录不是强制首屏；收藏同步等动作需要登录时再给出二维码登录入口。首次进入空间播放，提供“摆到舒服的位置”和“稍后调整”两条路；控制器可直接操作。手势引导只在启用手势时出现。

原型提供“登录流程示意”与“模拟已扫码”状态，明确不是可扫码的真实二维码，不收集账号密码。

### B. 找片与接着看

发现页：搜索置顶，继续观看优先，下面是分区和视频卡片。卡片展示标题、UP、时长、内容类别，不铺满互动数字。选卡片进入详情；详情包含简介、选集、播放、稍后再看。

搜索：提交后展示结果；清空回到发现。无结果时保留关键词并提供清空；没有网络时保留已有列表和重试。我的：稍后再看和历史两个入口；历史按最近观看排序，保留每条进度，不自动清除。

### C. 空间观看

默认“专注”：一个主屏，下方控制条。按“选集”展开左侧组件，按“评论”展开右侧组件。展开/收起组件时，为未锁定的主屏自动调整留白；已锁定主屏保持原位，用户可主动进入摆放。切换集数保持画质偏好、布局和字幕偏好，进度按各集独立记录。

“桌面”：主屏 + 选集 + 评论。“陪伴”：主屏 + 评论；弹幕沿用用户此前设置，不因为切换布局而自动开启动画或声音。

退出播放：暂停并保存本地进度，回到原来的内容页；再次进入恢复进度。完整看完的分集再次点播放时从头开始。播放结束显示重播、下一段、返回详情；V1 默认不自动播下一段，避免用户离开视线后继续播放。

### D. 摆放组件

点击“摆放”进入显式编辑态：标题栏出现拖拽柄；内容区仍用于选集/评论，不承担拖拽。可选主屏/选集/评论，调整大小、远近与平面位置；锁定后不能拖拽，必须显式解锁。

每个辅助面板可选择“跟随主屏”或“留在空间”。“跟随主屏”是组关系，不是跟随头部转动。主屏移动时只带动未锁定且设为跟随的组件；锁定优先于组移动。

“召回窗口”把当前可见窗口带回视野内，保留大小、透明度和组件选择；“恢复此布局”才重置当前布局的窗口参数。预设各自保存，不因为切换预设丢掉上次摆放。靠近预设停靠位置时吸附，显示位置预览；桌面原型只示意屏幕内位置，不模拟世界坐标持久锚定。

### E. 弹幕

普通弹幕默认低密度，屏幕中部上方区域内出现，避让底部字幕；可完全关闭。河流作为用户主动开启的空间试用项，从主屏下方单独通道经过，避免上下层同时滚动。实际运动速度、深度、同屏数量以真机测试结果确定。

原型的“预览一次”使用固定示例文本，不连接 B 站；河流表现只是二维透视动画。跳出和朗读放在折叠实验区：一次一条，不随机靠近脸部，不自动朗读；停止按钮同时停止效果和语音。朗读可用性依赖浏览器声音，未声称空间音频。

## 5. 视觉与交互规则

| 元素 | 设计 |
| --- | --- |
| 视觉 | 中性浅/深表面，少量 PiliPlus 粉色用于主操作和选中态；空间环境低对比，片源内容占主导 |
| 主屏 | 平面 16:9；内容按原比例留边，不拉伸；控制条独立于画面，不压字幕 |
| 辅助面板 | 默认背景不透明度 88%；可调 35%–100%；文字、按钮保持实色；评论密集时推荐提高背景不透明度 |
| 环境 | 独立明暗滑杆；不通过淡化视频或文字达到变暗效果 |
| 字号 | 桌面原型验证层级，不把 CSS 像素直接当头显字号；头显需按角尺寸和实际观看距离校准 |
| 距离 | 原型 1.5–3.5 m 为布局假设；桌面只用透视缩放示意，不能验证清晰度或眼部舒适度 |
| 射线 | 悬停反馈 → 点击；滑杆支持离散步进；拖拽和点击使用不同区域 |
| 手势 | 捏合选择；只抓标题栏移动，双手缩放留待真机验证；提供按钮调整的等价路径 |
| 返回 | 一级返回关闭设置/摆放，二级回内容面板；不立刻退出应用 |
| 恢复 | 每种布局保存组件开关、位置、大小、远近、透明度与锁定；新一集保持布局 |

桌面小尺寸预览会把窗口纵向排列，以保证可读和可操作；这仅是评审工具的响应式表现，不是 Quest 布局规范。头显的固定参照、坐姿/躺姿、离开边界后的恢复，需要等比例原型确认。

## 6. 原型覆盖与限制

可操作：发现/分类/搜索、详情/选集、稍后再看、历史/续播、播放计时/拖动、预设/组件开关、编辑/锁定/召回、透明度/环境、弹幕示意、登录状态示意、播放错误/结束状态预览。

原型使用虚构示例内容和原创插画；计时是交互模拟，没有视频解码、B 站请求、真实扫码、账号同步、真实透视、六自由度或空间音频。画质和倍速用于评审设置流程；倍速改变示例计时，画质不会改变真实清晰度。示例用户已有一条观看记录；首次头显引导在本稿中定义，原型未展开单独的引导页面。

专用“评审状态”控件属于评审工具，位于应用界面之外，可预览正常/加载/失败/结束。正式产品不出现这种控件。

## 7. 评审任务和进入开发的条件

| 阶段 | 任务 | 通过依据 |
| --- | --- | --- |
| 桌面流程 | 搜“旅行”→开详情→播放→打开选集→切换→返回历史续播 | 页面去向清楚；进度、选集、稍后再看状态一致 |
| 桌面空间 | 桌面布局→改变辅助透明度→锁定选集→移动主屏→召回→切换布局再回来 | 锁定和跟随规则一致；召回不等于恢复默认 |
| 桌面异常 | 无搜索结果、播放失败后重试、结束后下一集、登录过期入口 | 不丢关键词/进度/布局，用户知道下一步能做什么 |
| Quest 等比例 | 坐姿、躺姿、控制器、手势，主屏与两辅助面板；完成相同任务 | 读得清、点得到、不误拖、转头负担可接受；由用户体验判定，未验证 |
| Quest 舒适度 | 关闭弹幕/普通/河流分别观看，检查字幕遮挡和运动干扰 | 用户可接受且可以随时关闭；若河流失败则不进入首版 |
| 技术验证 | PiliPlus 播放基线，一个业务面板与独立视频输出，再验证多组件 | 真机视频、输入、生命周期和性能证据；详见现有测试计划，当前未执行 |

设计确认后按五个功能边界组织开发：内容与账号、统一播放会话、窗口与布局、环境与输入、弹幕。先打通找片到稳定播放，再加空间组件，最后决定是否发布河流效果。技术选型须重新核对当时的 SDK 和依赖，不以这个原型证明可行性。
